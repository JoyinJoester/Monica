# 自动填充独立强化验证（1.0.320，2026-10-15）

本轮在渐进升级交付后单独进行，复用原有自动填充链路，对连续实际操作、错误目标、保存完整性和授权撤销进行回归。此前功能交付报告保留不改写。

## 本轮修复

1. 无障碍补充填充仍按普通密码给新密码控件打分，可能将已有密码填入注册／改密／重置的输入框。新增四个行为用例，在 API 29、34 各复现四项失败；修复为复用系统解析器的新密码语义，并在候选评分和未知字段兜底之前排除。动态输入事件把旧密码控件替换为新密码控件时也重新检查。
2. 自动填充保存页单独验证成功不会解锁主应用；主应用已经锁定时，再执行锁定不改变布尔状态，原保存页因此未关闭。API32 设备用例确认锁定后 Activity 仍为 RESUMED。新增递增的锁定通知，保存页监听并关闭；不修改密码校验、会话超时或保留授权策略。
3. 解析器把浏览器访问的 `127.0.0.1`／`localhost` 页面当作混合应用内部 UI，丢弃网页来源，导致匹配不到已保存凭据。现在根据系统提供的 Activity 包名区分已知浏览器，浏览器保留原始来源；普通混合应用保留原兼容行为。真实 Chrome 的本机登录和注册均已通过针对性验证，注册只填用户名，不覆盖新密码。
4. 长时间连续测试复现动态网页“用户名已填、密码仍空”但服务报告成功。WebView 的写入动作确认先于异步控件更新，原来的成功判断没有再次检查目标。现在写入后等待有界的渲染更新，核对窗口／应用／浏览器来源，刷新密码控件并重新检查角色和空值，必要时交给原有的有限重试；不记录或导出密码内容，保留内容被隐藏、遮罩和显式未知密码框的兼容性。空控件负例在两个主机 API 均先失败再修复，遮罩正例通过；设备动态网页用例加为连续四轮。
5. 冷启动绑定验证器查询超过请求内的 100ms 预算，会漏掉选中凭据后的 OTP 回调。设备复测已经完成真实内联建议选择及密码填充，但没有验证码通知；未完成的绑定索引在两个主机 API 下也复现遗漏。现在查询超时保留候选的选中后回调，届时再检查真实设置和绑定；未绑定、无有效验证码或通知关闭的条目不发送通知，填充请求仍保持短时限。

## 覆盖情况

- 系统下拉建议、Gboard 内联建议、手动选择器、验证返回、取消／重试、选择器重建、禁用字段后拒绝先前发出的数据集和解锁请求。
- 原生登录、中文工号／学号与非标准输入类型、账号后密码两步登录、帮助 WebView 与原生表单共存、动态 WebView、多个 HTML 表单、浏览器计算提示。
- 注册不覆盖新密码，改密保留旧密码且生成值只进入新密码／确认框，取消生成不改值；无障碍注册和聚焦新密码的改密流程。
- 连续四轮原生登录→双表单 WebView→注册，核对另一表单保持空白；修改数据库密码后下一请求必须使用新值。
- 多账号、多密码和账号各自 OTP；内嵌银行卡、地址和证件；验证码通知仅在有效凭据选中后发出，取消验证、关闭通知、无 OTP 和无效 OTP 均保持原行为。
- 真正的 Android 保存提示→选择更新→共享编辑器→读取数据库。保存新密码、跨步骤恢复账号；保留兄弟账号、分组、自定义字段、收藏、文件夹、历史和 1024 字节真实加密附件，验证解密字节不变。
- 锁定保存必须验证、取消不写入、主任务移除、熄屏、服务重绑定、保留授权开关、错误密码、跨网站不复用授权，以及真实等待两分钟后的授权到期。
- 4096 字符密码、中文和 emoji、组合 Unicode、前后空格；随机排列字段仍保存精确原值，大小写／空格／Unicode 表示不同的确认值必须拒绝。
- 账号上下文恢复的八份历史边界、最近账号选择，以及用户信息段、伪后缀、路径伪装、非 HTTP 协议等 URL 不得建议更新无关原条目。
- 小保险库与加入 1000 条额外条目的保险库，以及额外 300 个节点的长表单；记录建议出现耗时，核对连续操作后的匹配和填充值。

## 失败及复测记录

- 旧 APK 首轮完整 60 项：58 通过、2 失败。银行卡选择失败源于测试直接修改 DataStore 后未同步恢复 SessionManager 的运行时超时；修正测试 setup/teardown，再整组验证。另一项是 WebView 键盘组合输入未找到测试键盘，保留首次记录并在最终整组重测，不用 ACTION_SET_TEXT 替代真实键盘操作。
- 新用例首轮 6 项：4 通过，两个测试定位错误。多表单 fixture 的状态名为 `newsletter`，测试误写为 `other`；Chrome 没有暴露 placeholder 为可访问提示，改为定位 WebView 内可编辑控件，排除地址栏。均保留首次失败记录。
- 保存页再次锁定的负例先取得明确失败，再修复并复测。无障碍四类负例保留主机 XML 证据。
- 一次重叠 Gradle 调用遇到 Windows R.jar 文件占用；结束前一构建后重试成功。后续同一项目构建顺序执行。
- 普通版中途整组 75 项有 5 项失败：两个页面驱动问题（缓存的 WebView 子节点、同步 DOWN 事件被阻塞成意外长按）修正后通过；动态网页写入假成功、绑定 OTP 冷查询漏回调分别形成产品修复。内联测试先有键盘未显示建议的失败，冷启动复测已经真实选中内联建议并正确填充，但缺少 OTP 通知；这两个失败阶段分别记录，没有合并为同一原因。
- 设备曾出现约 19.3 秒的系统渲染帧延迟，将 UI 等待从 10 秒改为 20 秒；应用请求的耗时另行记录。动态网页用例等待服务现有的完成消息后再检查字段并进入下一轮，避免上一轮异步操作与下一轮 fixture 重叠。

- F-Droid 最终有效整组 71／75。除了两个 WebView 键盘用例，连续切换场景的一轮 HTML 已可见但虚拟控件树没有内部输入框，测试未能开始点击；另一轮改密对话框的“使用”点击没有触发接受回调（只有打开及测试清理时的取消日志），因此未进入生成密码回填。相同 APK、相同断言单独复测这两个用例均通过（2／2），未调整代码、增加点击重试或跳过断言；仍将整组记为 71／75，并保留间歇性 UI 自动化失败，不能据单次复测宣布彻底消失。
- 普通版最终整组同样为 71／75：两个 WebView 键盘用例失败，首个锁定用例被设备尚未退出系统锁屏的 setup 检查拦下，动态网页的一轮也在点击前缺少虚拟输入控件。原样补测两项为 1／2：锁定用例通过，动态网页这次已经进入选择器，但出现合法的主密码验证页，测试原来只等待直接显示凭据列表。日志表明选择器查询主会话时触发了锁定；主任务移除保护会撤销测试直接建立的会话，不能绕过这一保护。仅修改手动选择器测试驱动：如要求验证，输入合成测试主密码并点“解锁”后再选择；实际填充值和动态网页四轮断言不变。

## WebView 154 键盘兼容性限制

公共虚拟机的 Android System WebView 为 `154.0.8037.107`。系统下拉建议出现后，WebView 丢失窗口焦点、主动隐藏输入法，并使输入连接变为空。没有替换成 ACTION_SET_TEXT，也没有给原“不重新聚焦即可输入”用例增加点击或跳过条件。

- 关闭自动填充的对照用例可以直接通过真实测试键盘组合输入。
- 使用临时的最小 AutofillService 对照：仅用 Android 的 AssistStructure、一个系统 TextView RemoteViews 和 Dataset，不加载 Monica 解析器、匹配器、数据库或认证代码。修正该对照最初错误选中容器节点后，同样显示建议后找不到输入法按键；失败位置为真正的键盘输入步骤。
- [Android 12.1 的 AutofillPopupWindow](https://android.googlesource.com/platform/frameworks/base/+/android-12.1.0_r1/core/java/android/view/autofill/AutofillPopupWindow.java) 将系统下拉窗口设为可聚焦；[WebView 154 同版本 ImeAdapterImpl](https://chromium.googlesource.com/chromium/src/+/refs/tags/154.0.8037.107/content/public/android/java/src/org/chromium/content/browser/input/ImeAdapterImpl.java) 的 `onWindowFocusChanged(false)` 调用 `resetAndHideKeyboard()`，与设备焦点及输入法记录吻合。
- Monica 通过公开 AutofillService API 不能修改其他应用的 WebView 或系统下拉窗口焦点。未加入反射修改其他进程窗口、吞掉焦点回调等侵入式处理。临时对照服务和诊断日志代码仅保留在本地任务证据中，不进入应用或最终测试 APK。
- 单独增加“重新点一次输入框恢复输入”的测试，以与严格的无二次点击测试区分：初次通过，但后续组合输入时建议重新出现，仍可能导致键盘隐藏，不能把一次点击作为可靠解决方案。结果见最终设备记录。不得将已确认的系统组件问题计入全绿结果，也不保证仅升级组件就一定修复所有设备。
