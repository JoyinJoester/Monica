# 自动填充渐进升级：浏览器提示与表单范围

日期：2026-10-14。版本：普通版与 F-Droid 1.0.320 未发布。

## 本阶段实现

在既有 EnhancedAutofillStructureParserV2 内升级识别，保留匹配、身份验证、数据集返回、存储和保存链路。参考本地 1Password 分析中可验证的浏览器提示与表单上下文思路，按 Android/HTML 接口独立实现。

- 解析 autocomplete、ua-autofill-hints 和 computed-autofill-hints。移除 section、地址/联系分组及末尾 webauthn 修饰，只精确匹配字段角色；拒绝含糊的多角色字符串，限制单个提示长度。
- 浏览器也会将 HTML token 放入原生 autofillHints 数组；这一路共用精确解析，避免 section-email 将密码框误判为邮箱。原生应用继续使用原来的提示和标签兼容逻辑。
- 区分当前密码、新密码和 OTP；掩码验证码不提升为密码，新密码不被 type=password 降级。保留搜索排除、autocomplete=off 偏好及已有联系人/卡片字段支持。
- 在既有窗口和网页来源隔离内，按焦点选取 HTML 表单，同时约束识别候选与 scopeAutofillIds。因此现有缓存恢复和兜底填充也遵守该范围。
- form 属性支持前向引用；重复或缺失的显式 ID 不合并无关字段，表单引用不能跨网页来源。没有表单信息的旧页面沿用原有网页范围。
- browserHintTokensEnabled 与 htmlFormScopesEnabled 是独立的实现开关，默认开启，便于代码级比较和回退；不是新增用户设置。

两版源文件与测试一致；不新增运行权限、依赖、联网服务或凭据上传。同步本地集成候选中的本阶段改动和说明，保留其其他实验改动；本次构建与设备结果针对普通版 main 和 F-Droid 工作分支。

主机测试包含 AutofillStructureIntegrationTest（API 29、34，共 66 项）、AutofillHtmlHintTokensTest，以及现有检测策略、字段角色、响应认证兼容、请求取消、请求上下文、手动目标和集成约束测试。覆盖分组前缀、OTP 别名、密码类型冲突、未知/过长提示、聚焦表单切换、同名表单、外部 form 关联、跨来源引用、未分类节点范围及独立回退开关。

最初新增场景在旧实现上产生 18 个失败；随后根据真实 Chromium 结构补充的原生提示数组测试也在修复前失败。修复后执行上述完整回归通过。

设备复用 Monica_Issue136_API_32（x86_64），在已有独立 Android 用户 10 执行，使用合成凭据且不访问真实站点。每版 11 项覆盖：

1. 无标签、仅 computed-autofill-hints 的控件，通过真实系统自动填充返回账号与密码。
2. 真实 WebView 的登录与订阅表单，包含 section-email 密码提示；登录填入，订阅保持为空。
3. 标准原生登录。
4. 关闭填充验证后，会话锁定时保留既有免验证行为。
5. 中文企业账号字段。
6. 原生登录旁的无关 WebView。
7. 同 Activity 的账号/密码分步登录。
8. WebView 填入及网页 input/change 事件。
9. 键盘 inline 建议选取。
10. 验证后返回原表单。
11. 取消验证保持空白并可重新填充。

测试准备中遇到模拟器 System UI 无响应弹窗，处理后重新执行。另修正测试夹具的域名父容器被 Android 裁剪的问题；inline 场景首次等待超时，单独复查及最终整组均通过。上表仅记录最终源码和安装包对应的完整通过结果。

两版安装前后核对 APK SHA-256。测试结束删除本轮合成记录，恢复验证偏好、系统自动填充、输入法、无障碍和屏幕超时设置，切回原用户 0。截图与调试日志仅保留本地，不入库。

## 验证边界与后续方向

computed 提示测试使用 Android ViewStructure 夹具；HTML 多表单归属的完整结构通过 API 29/34 测试覆盖，设备 WebView 本身也可能预先仅暴露当前表单。结果不代表所有浏览器、厂商系统和自绘控件均已验收。

本阶段完成提示解析与表单范围。后续登录/注册/改密流程识别、跨步骤上下文及超时体验可继续独立升级，不把本阶段视为完整替换自动填充引擎。
