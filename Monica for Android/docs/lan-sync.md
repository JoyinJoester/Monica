# Monica 附近设备全量同步

Android：设置 → 数据库与备份 → 常用同步 → 附近设备同步。Windows：同步与备份 → 附近设备同步。

两端请使用支持全量内容同步的新版。已有配对可继续使用；旧版密码同步客户端会收到更新提示。安装手机 APK 或解压 Windows ZIP 后启动 Monica。Windows 请先保存编辑内容并退出旧进程，再启动新版。

Android 11 补充旧通行密钥记录的准备处理：私钥有效但公钥缓存或算法字段缺失时，从原私钥恢复用于同步的信息，导出过程不修改本机记录。公私钥不匹配、私钥引用丢失或受保护材料无法解析时，会指出失败记录及具体步骤，保持同步未完成，不会生成替代密钥或将丢失的私钥假报为已同步。Android 10 的 SPKI/COSE 公钥支持保留。

两端 11 修复接收通行密钥元数据更新时清空本机原私钥的问题：先验证凭据和公钥身份，再保留本机私钥及备份状态。缺少公钥缓存时验证可导出的原私钥；系统密钥无法导出且身份无法证明时中止更新。Android 原生存储投影同时保留已有公钥缓存和算法，避免把 RS256、PS256、Ed25519 默认改成 ES256。

配对只登记设备身份，首次内容同步成功后才出现同步时间。准备失败时，设备状态显示“已配对 · 准备同步失败”；等待首次同步时显示“已配对 · 首次同步未完成”。同步完成后显示“最近一次同步成功”，并列出实际时间。

使用分身测试时，仅在分身内更新测试副本，正式应用无需删除。同步页面直接显示实际运行版本。复制诊断会自动包含版本、构建、Android API 和用户空间编号，以及 Room/原生记录来源和失败步骤。通行密钥名称只显示在页面中，不写入或复制到诊断。该版本尚未在用户的实际分身环境中验证，原有笼统错误码不足以确认该分身的具体原因。

一台设备显示配对二维码，另一台扫码。两台设备保持解锁并处于同一可互通的局域网，首次配对后自动同步。无需输入另一台设备的主密码或选择接收数据库。新内容进入本机默认 Monica 存储，已有内容在原存储中更新。

同步方向默认双向，也可选择本机仅发送或仅接收。一次传输遵守双方设置，双方都仅发送或都仅接收时提示方向不匹配。单向需要两端都支持方向控制；旧客户端可继续双向同步。切换方向会中止旧传输并保留配对，重启后保留选择。详细规则见 [device-sync-direction.md](device-sync-direction.md)。

发送前会复用通行密钥迁移弹窗，列出本地及可用 Monica MDBX 中无法跨设备或跨平台使用的通行密钥。可取消同步（关闭自动同步并保留配对），或了解限制后继续；不可导出的密钥仅同步凭据信息，需在目标设备重新注册。检查也覆盖配对后的首次自动发送。已确认的条目及限制在本次应用进程内按接收设备记忆；新增受限条目、限制变化或新配对设备会再次提示。仅接收模式不检查本机发送限制。缺失或损坏的受保护私钥仍中止准备，不能通过确认弹窗绕过校验。

同步范围包括：

- 密码及完整登录字段、自定义字段、密码历史、归档、收藏、关联应用、SSH/Wi-Fi 数据、绑定笔记和关联账号。
- 独立 2FA：TOTP、HOTP 计数器、Steam 恢复信息及未知扩展字段。
- 通行密钥：凭据、公钥、可导出的 PKCS8 私钥、关联密码和文件夹。接收后重新保护私钥，并验证公私钥匹配。无法导出的系统或硬件密钥保留凭据信息，在接收设备上需要重新设置。
- 安全笔记、卡片、证件、地址、付款账户，及完整业务 JSON。
- 空文件夹、嵌套文件夹、项目和根目录标签、原生对象标签与关系、回收站中保留的内容。
- 文件附件、图片与上传图标。附件使用独立加密容器和 512 KiB 认证块，接收时验证内容并重新加密保存。单文件支持 64 MiB，单次附件容器上限为 512 MiB。

Bitwarden、KeePass 外部账户继续使用各自的同步机制。当前客户端没有编辑界面的扩展字段会随业务记录保留。内部数据库提交历史属于存储实现，采用业务记录同步。

Steam 范围包括验证器中的 Steam 类型、MDBX 的 `steam-mafile`，以及 Steam 页面独立的本地 `steam_database` 账户库。独立账户沿用 `steam-mafile` 格式，保留令牌、会话、未知字段和文件夹，接收端重新加密；同一 Steam ID 的多份独立记录不合并。选择当前 Steam 账户属于本机界面状态，不参与同步。

两端显示准备、传输和保存的动态进度，条目进度使用所有待保存批次的总数，附件显示实际字节进度。完成校验、保存和关联恢复后才显示成功同步时间。缺失附件、损坏内容或无法处理的对象会使同步保持未完成，并显示诊断。

“自动同步”默认开启，频率可选实时或 1–1440 分钟；频率设置也同步到配对设备。锁定、后台限制或正在编辑时暂停应用更新，解锁和重连后补同步。离线并发修改使用版本向量，不能直接合并的内容保留冲突副本。取消配对会保留两端内容。

双方使用 Noise 加密连接；首次扫码建立长期设备密钥，后续验证身份。逻辑日志、临时快照和附件容器均加密，不交换主密码。Windows 使用系统保护保存配对信息，Android 使用应用加密存储。旧版 08 的 8 MiB 原生请求修复、07 的硬链接受限环境回退及批量删除进度继续保留。

本轮使用隔离的合成保险库和真实 Rust、Windows 原生引擎、Android Room 数据库执行回归。回归覆盖真实 Room/共享 Rust JNI、原生引擎、通行密钥和内容同步，并补充方向、设置保存、切换和进度结束的验证。Android JNI 与 Windows 共享核心包含相同的方向控制代码，手机安装包提供 arm64-v8a、armeabi-v7a 架构。本机没有连接 Android 实机，因此手机与电脑、手机与手机的实际 Wi-Fi 联调尚未验证。

遇到连接失败，请复制页面中的连接诊断。首次连接尝试二维码提供的 IPv4 网卡地址，重连使用已知地址和组播发现；访客网络、客户端隔离或防火墙可能阻止直连。诊断仅记录阶段、错误码和操作信息，不包含密码、私钥或配对密钥。
