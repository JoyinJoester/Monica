# Vaultwarden 首页与搜索可见性验证

2026-10-09；普通版与 F-Droid。

## 结论与复现

使用内存 Room 数据库和真实 VaultV2Pane，构造一个已解锁的自托管 Vaultwarden 来源：515 条密码、4 个远程证件、1 个本地证件。服务器地址使用 example.test，未连接用户服务器。

旧版 VaultOverviewConfig 默认 scope 为 local；旧 JSON 缺省 scope 时也恢复为 local。首页计数和首页搜索都基于同一范围投影，所以远程条目已在数据库中，首页仍呈现 0 密码、1 证件。修复前新增设备测试在密码数量断言上失败：expected 515 but was 0；配置测试同样在 all/local 上失败。

切到 All 后，首页显示 515 密码、5 证件，搜索 Vaultwarden login 514 能显示并打开 id=1514 的合成密码。手动选择 local 仍只显示本地证件。动态锁定远程库后，All 范围也立即排除远程条目。

## 修改

- 默认 scope 改为 all，新安装和旧版未存范围的配置均采用该值；其他投影、搜索与锁定逻辑保持原实现。
- JSON 中明确保存的 local、Bitwarden、KeePass、MDBX 范围继续保留，并覆盖保存／重新读取测试。
- 兼容限制：旧版序列化会省略默认 local，即使用户曾手动选择过它；缺省字段无法区分该操作和从未设置范围，这些配置都会转为 All。升级后再次选择本地库会明确保存 local。
- 默认值相关的两条现有界面断言同步更新；新增测试等待真实结果行，而非与查询相同的输入框文字。

## 验证结果

两版 assembleDebug、assembleDebugAndroidTest 成功；每版 17 项单元测试和 7 项设备测试通过。单元测试覆盖配置升级／持久化，以及范围、锁定、计数和推荐投影。设备测试逐方法独立运行，覆盖以下场景：

1. 缺省旧配置下，515 条远程密码的首页计数、类型列表、搜索与打开。
2. 明确选择本地库复现反馈，UI 切换 All 恢复，远程库锁定过滤。
3. 类型列表进入与返回。
4. Bitwarden 经典列表、文件夹、收藏和归档导航。
5. Bitwarden 层级列表、文件夹、收藏和归档导航。
6. 首页搜索、键盘提交、点击结果及返回时保留范围和滚动位置。
7. 关闭概览后恢复经典列表的已保存范围。

结果、测试包哈希和合成页面截图见 results.json、Main-device.log、Fdroid-device.log 及 screenshots/。

早期验证记录包括预期的修复前失败，以及测试自身的首帧／系统锁屏、等待条件、旧默认值断言问题；最终测试恢复系统锁屏设置并等待真实页面和结果条目。未通过的运行不计入通过结果。没有运行完整仓库测试套件，也没有访问反馈者的服务器或实机；本记录证明该默认范围问题能复现并已修复，不能排除反馈者还存在其他环境问题。
