# URL 匹配规则与 M3E 编辑菜单验证（2026-10-21）

Issue: https://github.com/Monica-Pass/Monica/issues/171

## 行为与数据

- 每条网站 URL 可在右侧三点菜单设置默认、主域名、主机名、前缀、精确 URL、正则表达式或从不匹配。确认后生效，取消不改动草稿；上移、下移、删除时规则跟随对应 URL。
- 主机名区分生产与测试子域，不折叠 www；主域名使用公共后缀及私有后缀边界，避免把不同 github.io 站点合并。IP 与 localhost 保留实际主机边界。
- 网站规则按任一 URL 命中推荐。明确规则不再通过标题或宽松回退绕过；默认 URL 保留全局域名策略。Android 应用绑定仍走现有应用匹配路径。
- 正则采用 RE2J，限制表达式长度，拒绝无效或不支持的语法，避免回溯型正则阻塞填充。前缀比较先校验协议、主机和端口；裸主机前缀只接受同一完整主机。
- 规则存于已有自定义字段管线的保留字段 `monica.autofill.url_rules`，保留 URL 原文、大小写和正则中的逗号／竖线；全部恢复默认时删除该字段。无需数据库列迁移。异常、重复或未来版本数据不回退为更宽松推荐，编辑器保留原数据并禁止覆盖保存。
- 本次没有把此保留字段转换为 Bitwarden 原生 `uri.match`，不宣称其他客户端会解释 Monica 的规则。已有自定义字段保存、备份与同步管线继续承载该字段。
- 系统填充服务及输入法／主动填充打开的账号选择页共用这些规则；原生索引额外保留具有自定义 URL 规则的候选，规则单独变化即可生效。

- 验证器高级参数入口使用相同菜单。URL 匹配与密码内验证器参数使用居中弹窗；URL 选项可滚动，确认和取消保持可达。
